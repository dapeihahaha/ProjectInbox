# 数据边界、完整性与恢复

## 唯一任务库

当前任务采用 Backlog 原生 UTF-8 Markdown + YAML Front Matter，唯一来源为 `backlog/`。活动任务在 `backlog/tasks/`，收起的已完成任务在 `backlog/completed/`，其他归档在 `backlog/archive/tasks/`。Project Inbox 能检索三处内容，归档记录为只读。

编号为 TASK-1 形式，跨项目共享，归档不改变编号；本机补丁避免原版复用归档 ID。原生文件时间为 UTC、分钟精度，MCP 转换为 settings 中的 America/Los_Angeles 时间。正文遵循 Backlog 的 DESCRIPTION / NOTES 区块；保留区块标记，避免删除未知的原生字段。

任务写入交给 Backlog 原生 CLI 或 Web；它们使用原生文件写入与编号锁机制。Python 包装层另用 `.inbox.lock` 协调自身的多步骤操作。两层锁不能防护手工并发覆盖，也不代表整个多文件操作是数据库事务。不要让编辑器与工具同时改同一条任务。

旧版 `data/.history` 自动快照机制已停止使用；新版没有每次更新前的自动历史备份。旧 `data/` 未删除但不再作为任务来源。定期完整复制 `backlog/` 与 `config/` 到本地备份位置，备份时停止写入以获得一致快照。

## 检查

```bash
/Users/wangyichuan/.local/bin/project-inbox check
```

检查任务 Front Matter、ID 与文件名前缀、已知状态、时间可解析性、重复 ID、符号链接及文件读取大小。异常返回非零；常规查询与包装层写入会拒绝损坏库。检查不等于备份，也不代替原生全部字段语义验证；直接从页面写入的内容应保持配置约定。

读取单文件上限 256 KiB、单库扫描上限 10000 条。包装层限制标题 500 字符、单个正文字段 20000 字符、标签 50 个；搜索默认 50、最多 200 条，无分页。页面原生操作的限制可能不同。

## 恢复

1. 关闭 Cherry 的该 MCP，按后台服务文档用 launchctl bootout 停止看板，再停止其他 CLI / Agent 写入；只终止看板进程会触发自动恢复。
2. 先复制整个 `backlog/` 与 `config/`，保留异常原件；不要直接覆盖。
3. 根据 check 提供的路径，对照自己保留的备份，确认恢复对象、编号、内容和状态。没有备份时不能假定工具可恢复旧正文。
4. 重复 ID 或移动中断留下多个文件时，逐一比较并确定有效版本。把不采用的原件移到 `work/recovery/` 等任务扫描范围外保留，不自动合并或删除。
5. 恢复后执行 check，再对具体编号执行 show；核对正确后重开 MCP 和看板。

恢复真实文件涉及覆盖、迁移或批量处理时，先展示对象、版本与风险并由用户确认。本次未执行真实任务恢复。切换前快照在 `work/legacy-before-backlog-2026-10-14/`，只用于回溯旧实现；它不是新任务的自动备份。

## 边界

MCP 仅提供项目和任务工具，不提供任意路径、Shell、永久删除或自动编码。适配层拒绝任务路径符号链接与回调命令配置。看板只监听 127.0.0.1；不开放局域网，不提供多用户鉴权，适用于本机个人使用。

项目发现只在配置根目录与深度内读取 Git 标识、提交时间、文件修改时间及已入选项目的白名单简介；不读取会话正文，不执行项目代码。纳入最近三个月符合条件的全部项目，保留既有记录，具体规则见 [项目发现](project-discovery.md)。Git remote 去掉账号、query、fragment，不联系远程仓库。

任务和 MCP 服务在本机，但 Cherry 发给现有模型服务的上下文仍遵循该服务的数据路径；不要在任务内记录凭证或敏感实验数据。卸载前停用 MCP、停止看板并备份本库，勿删除业务仓库或 Agent 会话目录。
