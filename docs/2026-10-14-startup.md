## 三、项目自动发现

我的本地开发项目主要位于以下三个目录：

- `/Users/wangyichuan/localissue/`

### 活跃项目选择

1. 先检查本机三个 Agent 实际可用的会话索引或元数据来源，不假定固定路径或存储格式，也不要求三个 Agent 都有可用记录。
2. 只读取识别项目路径及最近会话活动时间所需的最小元数据，不读取对话正文、提示词、工具输出、凭证或实验数据；不修改会话文件或 Agent 配置。
3. 只纳入能确认属于上述三个目录范围内、且当前路径存在的项目。先归并同一项目的重复仓库与 worktree，再排名。
4. 第一版以项目在三个 Agent 中最近一次可核实的会话活动时间降序排列；同一项目跨 Agent 活动取最新时间。并列时按规范化项目路径排序，确保结果可复现。
5. 不以目录修改时间代替会话活跃度；无法核实活动时间的记录不参与排名。可确认的项目不足十个时，按实际数量纳入，不为凑数而全盘扫描。
6. 交付时说明使用了哪些会话来源、排名依据和缺失来源，并列出入选项目及最近活动时间。若没有可用元数据，先报告缺口，再确认替代的项目清单或有限发现方式。

### 发现规则

1. 检测 Git 仓库，包括常规仓库和 Git worktree。
2. 识别 Git 仓库根目录。
3. 从 README、package.json、pyproject.toml 等文件中提取项目描述。
4. 读取 Git remote 作为项目辅助标识，但不访问远程服务。
5. 自动识别重复仓库与 worktree。
6. 排除 node_modules、.next、dist、build、.venv 等目录。
7. 限制扫描深度，避免无限递归。
8. 不读取 `.env`、密钥、数据库或其他敏感文件内容。
9. 不执行仓库内脚本，不安装仓库依赖。
10. 不能确定项目描述时，保留空值或标记待确认。

生成 `config/projects.yaml`。

每个项目包含：

- id：稳定的唯一标识
- name：项目名称
- aliases：项目别名
- path：主项目路径
- worktrees：其他工作树路径
- description：简短项目简介
- keywords：关联功能关键词
- enabled：是否参与自动匹配

不预设 EditR_wang、newn8nbase、lab-workspace 必须入选；项目名称与路径以真实文件系统及会话活动记录为准。未入选的其他项目不自动加入首次注册表。

禁止仅根据目录名臆造项目功能。

### 注册表更新

提供 `refresh_projects` MCP 工具，用于按相同的会话活跃规则重新发现项目，并核对已有注册项目的路径状态。

更新时：

- 保留用户自定义的 aliases、description 和 keywords。
- 将本次活跃度排名前十中的新项目自动添加。
- 已有项目不因跌出前十而删除、自动禁用或影响其任务；前十限制用于每次发现候选，后续注册表总量可以超过十个。
- 不存在的项目标记为 missing，不直接删除。
- 使用 Git common-dir / remote / 路径综合判断 worktree 关系。
- 新扫描结果与旧注册表合并。

## 四、MCP Server 功能

使用官方 MCP SDK，提供以下工具。

### 1. list_projects

列出当前所有已注册项目，包括名称、别名、简介和可用状态。

### 2. match_project

输入自然语言描述，返回可能关联的项目。

使用项目名称、别名、关键词及描述匹配。

返回：

- 候选项目
- 匹配依据
- 匹配置信度或匹配等级
- 是否存在歧义

明确项目名称优先。

如果多个项目匹配，不要强行选择。

需要区分：

- 精确匹配
- 高置信推断
- 模糊匹配
- 无法识别

项目匹配功能尽量使用简单的确定性规则，不额外调用云端模型。

### 3. create_task

创建任务。

输入字段：

- project_id
- title
- type
- description
- expected_behavior
- reproduction_steps
- priority
- tags

支持字段缺省。

任务类型：

- bug
- feature
- improvement
- investigation
- idea

任务状态：

- inbox
- todo
- in_progress
- blocked
- done
- archived

优先级 P0–P3，默认 P2。

所有任务使用全局唯一且稳定的 ID，避免并发冲突。

如果无法确定项目，写入全局 inbox。

不要强制用户填写所有字段。

### 4. search_tasks

支持：

- 关键词搜索
- 按项目过滤
- 按任务类型过滤
- 按状态过滤
- 按优先级过滤

返回精简结果。

### 5. get_task

通过任务 ID 读取完整任务。

### 6. update_task

允许修改标题、描述、状态、优先级、标签、关联项目等字段。

更新时保留创建时间，记录更新时间。

### 7. find_duplicates

创建任务前，查找同项目中可能重复的任务。

第一版使用关键词、文本相似度或其他轻量级算法，不要求向量数据库。

返回候选任务，由智能体或用户决定是否合并。

不得自动删除已有任务。

### 8. archive_task

将已完成或不再需要的任务归档。

任务 ID 保持不变。

不得直接永久删除文件。

### 9. refresh_projects

根据三个 Agent 的本机会话活跃情况刷新候选，核对已有项目并更新项目注册表。

### 10. get_project_tasks

获取某个项目的任务列表，支持按状态筛选。

10. 支持将来迁移到其他工具，不引入私有存储格式。
